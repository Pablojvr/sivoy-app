# Arquitectura de Base de Datos - Sistema de Logística 📦 (Fase 2)

He actualizado el modelo de la base de datos para incorporar la nueva estructura de datos extraída mediante análisis de imágenes. El diseño ahora incluye una mejor categorización geográfica (departamento, municipio) y una separación total de los `horarios_operativos` y `reglas_entrega`.

## 1. Modelado DDL (Oracle SQL)

```sql
-- CATÁLOGOS (Diccionarios para estandarizar textos)
CREATE TABLE CAT_TIPO_DESTINO (
    id_tipo_destino NUMBER PRIMARY KEY,
    descripcion VARCHAR2(50) NOT NULL UNIQUE
);

CREATE TABLE CAT_DIAS_SEMANA (
    id_dia NUMBER PRIMARY KEY,
    nombre_dia VARCHAR2(20) NOT NULL UNIQUE
);

CREATE TABLE CAT_REGLAS_CORTE (
    id_regla_corte NUMBER PRIMARY KEY,
    descripcion VARCHAR2(50) NOT NULL UNIQUE
);

-- Entidad Principal: DESTINOS
CREATE TABLE DESTINOS (
    id_destino VARCHAR2(50) PRIMARY KEY, -- Ej: 'AG_SAN_MIGUEL_01'
    nombre_destino VARCHAR2(100) NOT NULL UNIQUE,
    id_tipo_destino NUMBER NOT NULL,
    departamento VARCHAR2(100),
    municipio VARCHAR2(100),
    direccion_referencia VARCHAR2(255),
    CONSTRAINT fk_destinos_tipo FOREIGN KEY (id_tipo_destino) REFERENCES CAT_TIPO_DESTINO(id_tipo_destino)
);

-- Entidad: HORARIOS_OPERATIVOS
CREATE TABLE HORARIOS_OPERATIVOS (
    id_horario NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_destino VARCHAR2(50) NOT NULL,
    id_dia NUMBER NOT NULL,
    hora_apertura VARCHAR2(5) NOT NULL, -- Formato 'HH:MM' (24h)
    hora_cierre VARCHAR2(5) NOT NULL,   -- Formato 'HH:MM' (24h)
    CONSTRAINT fk_horarios_destino FOREIGN KEY (id_destino) REFERENCES DESTINOS(id_destino) ON DELETE CASCADE,
    CONSTRAINT fk_horarios_dia FOREIGN KEY (id_dia) REFERENCES CAT_DIAS_SEMANA(id_dia)
);

-- Entidad: REGLAS_ENTREGA
CREATE TABLE REGLAS_ENTREGA (
    id_regla NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_destino VARCHAR2(50) NOT NULL,
    id_dia_entrega NUMBER NOT NULL,
    id_regla_corte NUMBER NOT NULL,
    id_dia_corte_especifico NUMBER,
    CONSTRAINT fk_reglas_destino FOREIGN KEY (id_destino) REFERENCES DESTINOS(id_destino) ON DELETE CASCADE,
    CONSTRAINT fk_reglas_dia_entrega FOREIGN KEY (id_dia_entrega) REFERENCES CAT_DIAS_SEMANA(id_dia),
    CONSTRAINT fk_reglas_tipo_corte FOREIGN KEY (id_regla_corte) REFERENCES CAT_REGLAS_CORTE(id_regla_corte),
    CONSTRAINT fk_reglas_dia_corte_esp FOREIGN KEY (id_dia_corte_especifico) REFERENCES CAT_DIAS_SEMANA(id_dia)
);

-- Índices recomendados para optimización
CREATE INDEX idx_horarios_destino ON HORARIOS_OPERATIVOS(id_destino);
CREATE INDEX idx_reglas_destino ON REGLAS_ENTREGA(id_destino);
```

> [!TIP]
> Se ha cambiado la PK de `DESTINOS` a un `VARCHAR2` para aprovechar la nomenclatura generada automáticamente (`AG_...` / `PF_...`), lo cual permite identificar rápidamente agencias vs puntos fijos sin cruces de datos complejos.

## 3. Consultas RAW SQL (Casos de Uso)

Aquí tienes las tres consultas de negocio adaptadas al nuevo esquema:

### Consulta A (Búsqueda de ETA)
**Caso:** Dado un día de corte específico ('Martes') y un destino ('Anamorós'), ¿cuál es el próximo día de entrega disponible?

```sql
SELECT r.dia_entrega
FROM DESTINOS d
JOIN REGLAS_ENTREGA r ON d.id_destino = r.id_destino
WHERE d.nombre_destino = 'Anamorós'
  AND (r.dia_corte_maximo = 'Martes' OR r.dia_corte_maximo = 'Día anterior')
FETCH FIRST 1 ROWS ONLY;
```

### Consulta B (Planificación Inversa)
**Caso:** Si hoy es 'Viernes' y la hora actual es antes del cierre de agencia (Ej: son las `14:00`), ¿qué destinos recibirán paquetería exactamente el día 'Domingo'?

```sql
SELECT d.nombre_destino, d.tipo, h.hora_cierre
FROM DESTINOS d
JOIN REGLAS_ENTREGA r ON d.id_destino = r.id_destino
JOIN HORARIOS_OPERATIVOS h ON d.id_destino = h.id_destino
WHERE r.dia_entrega = 'Domingo' 
  AND r.dia_corte_maximo = 'Viernes'
  AND h.dia_semana = 'Viernes'
  AND '14:00' < h.hora_cierre;
```
> [!IMPORTANT]
> El campo `hora_cierre` en la tabla `HORARIOS_OPERATIVOS` está normalizado a un string militar (ej: `16:00`). Esto permite realizar comparaciones de tiempo directamente en la cláusula `WHERE` asumiendo que la hora inyectada (en el ejemplo, `14:00`) lleva el mismo formato.

### Consulta C (Cobertura Total Geográfica)
**Caso:** Muestra todos los destinos que tienen entregas 'Diario' agrupados por su departamento.

```sql
SELECT d.departamento, d.nombre_destino, d.tipo
FROM DESTINOS d
JOIN REGLAS_ENTREGA r ON d.id_destino = r.id_destino
WHERE r.dia_entrega = 'Diario'
GROUP BY d.departamento, d.nombre_destino, d.tipo
ORDER BY d.departamento, d.nombre_destino;
```
